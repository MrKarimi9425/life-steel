# Blog administration

The blog feature lives in `src/features/blog`. Route pages coordinate feature
components and hooks; API requests and data contracts are defined in `blog.api.ts`
and `blog.types.ts`. Form state uses Formik and validation uses Yup. Tables,
dialogs, actions, notifications and image cropping reuse the panel components.

## Routes

- `/blog/articles`: paginated articles, search, status/category/tag filters,
  ordering, editing, gallery, archive and permanent deletion.
- `/blog/categories`: translated categories with primary-category support in articles.
- `/blog/tags`: translated article tags.

All three tables support drag ordering and the existing 1,000-row page-size
option. Reordering updates the visible query cache optimistically and rolls back
on failure. Category and tag pages share their form, table and page composition.

## Article content

Persian titles are mandatory. The interface stays Persian and RTL; language
direction applies only to translated inputs and the block editor. Slugs are
generated by the server from titles on creation and editing and are not editable.

Article content is stored as Tiptap JSON, not HTML. The server validates node and
mark types, table structure, links and image ownership. An article and its Persian
translation must be publishable before the article can be published. Other
translations may remain drafts. Publishing is manual. Archive and permanent delete
are separate actions with confirmation dialogs.

## Article gallery

The gallery is a separate table action. It displays only images owned by that
article, with no shared library or video-upload action. Cropping and upload
progress reuse the existing scoped picker. Uploads are attached immediately;
closing the dialog does not undo successfully uploaded images. The cover selection
is saved with its own submit action.

Images inserted into article content must be selected from the saved article's
gallery. A new article must be saved before uploading its gallery. Images referenced
by any translation cannot be deleted until they are removed from the saved content.
Permanent article deletion removes its owned images. Incomplete file cleanup is
reported with a warning instead of an unconditional success notification.

The inline image dialog uses the shared `ImageSelectionGrid`: article-owned images
are visible as selectable cards, with a selected state and an explicit insert
button. Selecting an image does not upload files or change gallery ownership.

## Verified workflow

A separate disposable article was created as a draft, edited, manually published,
reordered with the editor drag handle, and archived through the panel. Publication
and removal after archive were verified on the public website. Permanent deletion
was verified through the backend service and the disposable record was removed.
The full multilingual demo article remains unchanged.

## Server state

Query keys and query options are shared in `blog.queries.ts`. The list response
does not include full block content or gallery assets. Article detail is fetched
only when its dialog is mounted. Gallery changes refresh article queries, not
unrelated taxonomy queries. Blocking query errors render a retry state; mutations
use the central toast mechanism and field errors are mapped into the form.

## Public API

The public blog endpoints return only published articles with a published
translation in the requested active language. They do not return other language
drafts. Related articles are derived from the primary active category and exclude
the current article. Articles without a category have an empty related list.
